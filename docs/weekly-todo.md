# 今週のTo Do

日報、会社の取り組み、既存の週次計画・レポートを維持し、個人の週間予定を別の画面で共有する機能。現在の公開基点は2026年10月22日版の `docs/production-current.md` を参照。名前での予定切り替え、画面下からの追加・保存・共有、日報連携、完了項目の折りたたみを保持し、未完了項目の自動引き継ぎを追加した候補。自動引き継ぎは本番未反映。

## 予定の表示と入力

- 初期表示は「みんなの予定」。名前は社長・管理担当者・担当者の順、同じ権限内は名前・IDの順で安定して並べる。社長を最初に選択し、一人分だけを縦の一覧で表示する。
- 名前を選ぶと対象の共有済み内容・当初目標・振り返り・履歴を確認できる。再読み込みや週移動でも選択を保ち、選択した利用者が一覧から外れた場合は先頭に戻る。
- 「自分の入力」は本人限定の下書きの編集画面。表示の切り替えでは入力内容を破棄しない。
- 画面下に「業務を追加」を固定表示する。追加時は本人の入力表示に切り替えて末尾に新規項目を追加し、業務名の入力欄へ移動する。既存項目の順番とIDを維持する。
- 編集中は下書き保存・共有も同じ操作欄で利用できる。スマートフォンでは既存の画面メニューより上に配置する。上限30件・保存中・競合時の追加制限を維持する。
- PCでもスマートフォンでも、共有予定と入力項目はそれぞれ一列で表示する。

## 運用

- 月曜日に「取り組む業務」と「金曜日までの到達目標」を入力し、本人が共有する。各項目の100％はその週の到達目標の達成を意味する。
- 従業員・管理担当者・社長が、それぞれ自分の予定を入力する。全員の共有一覧には社長も含める。
- 下書きは本人だけが閲覧できる。保存だけでは共有内容を変更せず、本人が共有した内容を社長を含む有効な利用者全員へ表示する。
- 進捗と実績は随時更新できる。「今週の振り返りを共有」で内容と日時を保存する。以後の共有更新は「振り返り共有後に更新あり」と表示し、再報告できる。
- 共有済みの項目は削除ではなく取り下げる。初回の目標、各共有時点、振り返りは履歴に保持する。
- 未完了の項目は日本時間の月曜0時に翌週の本人用下書きへ自動で引き継ぐ。共有前の下書きも対象にし、最新の保存済み内容で判定する。進捗100％・取り下げ済みは対象外。目標・進捗・実績と入力言語を保持する。過去週と今週の共有版・初回目標・振り返りは変更しない。
- 「自分の入力」を開いて引き継がれた項目と今週の目標を確認し、必要な内容を直して「共有する」を押す。下書きは本人だけに表示され、自動では共有しない。保存していない画面上の入力は自動引き継ぎの対象外。
- 今週の画面を開いた際にも自動処理を補完する。複数週使わなかった場合は最後の保存週から引き継ぐ。過去週・未来週の閲覧では自動処理しない。既存の今週の入力は末尾への追加のみとし、版番号の照合と取り込み元の記録で競合・重複を防ぐ。
- 30件またはUTF-8本文120KBの上限で追加できない場合、取り込み元の識別情報だけを引き継ぎ待ちとして保存し、画面に件数を表示する。下書きを整理して保存すると自動で追加する。待機分は翌週にも保持し、元の項目が完了・取り下げ・削除されていれば除外する。自動追加後に本人が削除した項目は同じ週に再追加しない。
- 週は日本時間の月曜日から日曜日、目標日は金曜日。曜日による入力制限を設けない。
- 画面は日本語・簡体字。共有本文、当初の目標、振り返り、変更履歴を表示言語へ自動翻訳し、原文も確認できる。翻訳失敗は保存から独立する。

- 日報を作成できる本人は、今週の業務の進捗や内容を更新すると「本日の日報に追加」から当日の業務メモへ追記できる。To Doは下書き保存し、共有版はそのまま保持する。同じ日の同じ更新を重複追加しない。詳細は [日報連携](weekly-todo-report.md)。

## 保存と認証

新規の `weeklyTodoWeeks`、`weeklyTodoHistory`、`weeklyTodoTranslations` を使用する。既存の `weeklyPlans` とそのAPI・日報・会社の取り組みの保存形式は変更しない。

週間文書は利用環境・本人・週の組み合わせで識別する。下書き、最新共有、初回共有、振り返りを分離し、共有ごとに追記型の履歴を作成する。共通の版番号をトランザクションで照合する。再認証による再送は同じ操作IDで重複登録を防ぐ。

読み取りも含め専用Callableを使用し、Firestoreからの直接読み書きを許可しない。保存対象は認証中の本人から決定し、代理対象の指定を受け付けない。社長を含む全員が自分だけを編集でき、他人の下書き閲覧・代理編集は不可。`president_viewer` という既存ロール名は維持し、今週のTo Doだけで本人入力を許可する。他機能の権限は変更しない。現在の有効状態、パスワード変更・再ログインの条件、Authの無効化、App Check、デモ環境の分離を維持する。

本文は原文と入力時の言語を保存する。翻訳APIには文書と共有版の識別情報だけを渡し、サーバーが閲覧権限を確認した原文を翻訳する。既存の `OPENAI_API_KEY` Secretを再利用し、新規キーや秘密値の書き換えは行わない。翻訳結果は本文の版・表示言語・利用環境・閲覧者で再利用し、原文を置き換えない。

初版では1週30項目、本文合計のUTF-8サイズ120KBまで。最初の目標、共有版、下書き、振り返りを同じ週間文書内に保存してもFirestoreの文書サイズ上限を越えないよう制限する。

架空データの確認画面は `npm exec vite -- --config tests/weekly-todo-preview/vite.config.ts` で起動し、`http://127.0.0.1:5211/tests/weekly-todo-preview/index.html?role=president` を開く。保存は画面のメモリー内だけに反映され、再読み込みで初期化する。実アカウント、Firebase、OpenAI APIには接続しない。
