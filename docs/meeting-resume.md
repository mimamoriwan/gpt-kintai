# 会議レジュメ：根拠付きAI整理（実装候補・本番未反映）

月末定例会議で、期間内の取り組み・進展・課題と判断事項を共有する本人専用の資料作成機能。

## 使い方

1. 「会議レジュメ」で期間（両端含む・366日以内）と対象者を指定する。「会社全体（全員）」も選べる。
2. 提出済み日報、会社の取り組みの投稿・変更履歴、共有済みTo Do・振り返りから情報源を選び、「AIで会議資料を作成」を押す。日報がない社長の記録も対象にできる。
3. 実際の処理段階（取得、全件読取、テーマ・図解の構成、照合）を表示する。失敗・キャンセルでは既存資料を置き換えない。未共有の下書きは取得・送信しない。
4. 全体の結論・要点、テーマ別の目的／実施／進展／課題／次の対応、会議で確認する問いと検討案を編集する。根拠番号から参照全文を確認する。
5. 時系列・テーマ間の関係・入力済みTo Do進捗を確認する。資料の要点は全体の記録、テーマ本文・図解は掲載選択を反映する。AIはテーマ全体の達成率を作らない。
6. 「要点・図解・会議の議題と根拠記録を確認した」を選び、PDF・配布HTMLを保存する。再編集すると確認は解除する。AIの照合は正しさを保証しないため、配布前に作成者が確認する。
7. 再編集用の下書きJSONを保存する。対象記録の全文を含むため保管用として扱う。配布物は参考資料の添付を明示選択した時だけ全文を含める。

「以前の作成方法（AI整理なし）」は全文のカテゴリ別取り込み・保存済み月次レポート利用を維持する。新しいAI作成とは明確に区別する。

## 情報源と期間

- 日報：期間内の提出済みのみ。仮作成・未提出・デモを除く。日本語では保存済み翻訳を優先する。元の記録・添付・確認状態は変更しない。
- 会社の取り組み：本人が共有メンバーで有効な設定の場合のみ。テーマ・案件の期間内変更履歴、期間内投稿を使用する。設定変更履歴や共有メンバー情報は送らない。状態・節目は各履歴時点の値で、現在の状態を過去に当てはめない。参照名が後日改訂されていれば、将来の名称を使わずID表示を維持する。
- 本人対象の会社履歴：本人が変更した履歴、または本人が担当する案件の変更履歴。投稿は本人が投稿したもの。作者名を保持し、他者の操作を本人の実績と断定しない。
- To Do：選択期間中に実際に共有・振り返りを保存した履歴だけ。週の開始日が期間外でも期間内の共有は含む。期間後の振り返りは含めない。`weeklyTodoWeeks`の下書きは本人分も含め一切読まない。項目を週・本人・IDでまとめ、途中の履歴を保持し、取り下げを表示する。
- 共有・投稿日時と実施日を区別する。進捗バーは期間内最終共有時点の本人入力値であり、案件の達成率や勤務評価ではない。
- 全件を取得・解析した上で重要な内容を会議向けに要約する。軽微・重複で本文に個別掲載しない記録も、番号と理由を確認できる。文字を途中で切る省略は行わない。

## AI処理

サーバー限定の既存 `OPENAI_API_KEY` を再利用し、Responses APIの `gpt-6.1-sol` を使用する。ブラウザーへキーを渡さない。新規キー発行・既存の日報AIや翻訳処理の変更は行わない。

1. 全記録を最大30件／おおむね6万文字の組に分け、実施・変化・課題・次の対応を抽出（medium）。すべての記録IDを一度ずつ処理できたことを検証する。
2. 元記録と抽出結果の両方から、カテゴリをまたいで関連案件をまとめ、要点・テーマ・時系列・関係・会議の問いを構成（high）。各文・図解に実在する根拠番号を要求する。
3. 原記録と資料を別リクエストで照合（high）。未実施の完了扱い、数字・日付・因果関係の創作、重大な課題の欠落、同じ成果の二重計上を検査する。問題があれば一度再構成・再照合し、なお不整合なら資料を返さない。

JSON Schemaに加え、参照ID・図のテーマID・期間・日付の根拠・全件の扱いをサーバーで検証する。モデル拒否・未完出力・形式不良・通信失敗時に従来の文字列連結をAI資料として代用しない。出力は `store:false` とし、サーバーDBに資料本文を保存しない。入力データ中の指示には従わないよう全段階で明示する。

上限は取得日報2000件、履歴各5000件、対象合計2000件／JSON 100万バイト、解析12組、1記録9万文字。超過時は自動で捨てず期間・対象者を分けるようエラーを返す。リクエストは最大540秒、AI全体は500秒で中断する。

## 本人限定・保存・配布

サーバーのアカウント管理オーナー判定を取得前・返却前に再確認する。ロールだけの管理者・社長・従業員・デモ・無効アカウントは生成できない。App Checkを要求し、共有設定も再確認する。同時生成を期限付きロックで防ぎ、中止・終了時に解放する。ロックはサーバー専用で本文を含まない。

同一ログイン中のメニュー移動は編集内容を保持する。ログアウト・再読み込みで消えるため、再編集用にJSONを保存する。自動保存・自動共有・他者への送信はしない。JSON上限20MB、本文1項目200万文字。超過時も文章を切って保存しない。旧下書きは保持して読込可能で、旧140文字切断が残る場合は配布を停止する。

配布HTMLは本文と共有CSSのみで、外部通信・外部フォント・スクリプト・アプリUIを含まない。Reactで文字列をエスケープし、CSPでスクリプト等を禁止する。印刷は独立iframeを使用し、A4縦・全文の折り返しと改ページを行う。実機の印刷改ページは別途受入確認する。
