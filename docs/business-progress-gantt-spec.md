# 「会社の取り組み」工程表の承認仕様

2026年9月7日。社長が工程表の画面イメージを了承したとのユーザー報告と、このイメージで開発を進める指示を受け、[第1段階の実装計画](business-progress-plan.md)へ追加する仕様。

## 承認された画面と意味

参照: [工程表の画面イメージ](/Users/itokazuyasushi/.codex/visualizations/2026/09/06/01a0787f-a504-74f0-a83c-857787822e49/company-initiatives-gantt.html)

- メニュー名は「会社の取り組み」。初期表示を工程表とし、従来の「一覧・近況」へ切り替えられる。
- テーマで行をまとめ、各行に取り組み名、担当、節目の完了数、予定期間の横棒を並べる。
- 横棒の位置と長さは予定期間。色に加え、文字・アイコンで未着手・取り組み中・保留・完了を示す。
- 「●●○ 2/3」は有効な節目3件のうち2件完了を意味する。作業量・工数の割合ではない。節目を均等な工数と仮定せず、会社全体やテーマの平均進捗率も算出しない。
- 行を選択すると、その取り組みの節目、最新近況、既存のお知らせ作成への入口を表示する。長い報告を読まなくても、全体の状態と節目の到達状況を把握できる。
- 工程表と一覧の絞り込みはテーマ・担当者・状態。選択した取り組みが絞り込み対象から外れた場合は、その旨を明示するか対象内の行に選択を移し、別の行の詳細と混在させない。
- 画面の日本語・中国語、スマートフォンでの表示、色だけに依存しない表現、キーボード操作を提供する。

画面イメージは挙動・配置の承認資料であり、製品コードとしてコピーしない。モックにはサーバー権限確認、永続保存、競合制御、本物の翻訳・発信はない。期間・担当・完了数・近況・例示した節目を、確認なしに本番実績として取り込まない。

## 予定期間

| 項目 | 保存・入力の方針 |
|---|---|
| 予定開始月 | `plannedStartMonth`: `YYYY-MM` または未設定 |
| 予定終了月 | `plannedEndMonth`: `YYYY-MM` または未設定 |
| 目標時期のメモ | 従来案の自由文を保持。「9月末」「先方回答後」などの補足 |

- 開始・終了をセットで保存する。両方未設定、または両方が有効な月で開始≦終了のいずれかを画面・サーバーで検証する。
- 単月と年越しを扱う。日時の時差による前月・翌月へのずれを生じさせない。
- 期間未設定の取り組みも担当・状態・節目を表示し、「期間未設定」と明示する。自由メモや投稿文から開始・終了月を推定しない。
- 表示範囲は実際の登録期間に応じて扱う。サンプルの2026年9月〜2027年3月や「9/7」を固定しない。現在位置を示す線は日本時間の当日を基準にし、表示範囲外なら誤った位置に描かない。
- 期間を変えても状態・節目の完了・近況を自動変更しない。予定超過の自動警告、依存関係、日単位の厳密な工程管理は追加しない。

## 節目と完了数

取り組みごとに必要な節目を少数から登録する。例は「保管条件を整理」「見積を比較」「利用倉庫を決定」。すべての取り組みに同じ段階数や名称を強制しない。

| 項目 | 方針 |
|---|---|
| 識別子 | 名称や配列の位置から独立した安定ID |
| 名称 | 原文を保存し、対象の現在版を日本語・中国語へ翻訳 |
| 表示順 | 管理担当者・社長が変更できる |
| 完了情報 | 完了／未完了、更新者、サーバー更新日時 |
| アーカイブ情報 | アーカイブ／復元を記録。履歴を物理削除しない |

- 節目は新機能内の取り組みに属するデータとして保存し、既存の業務メモ・日報には項目を追加しない。具体的な配置は確定基点の構造を確認して決めるが、取り組みと節目の更新を一貫して検証できる形にする。
- 分母はアーカイブされていない節目数、分子はそのうち完了した数。別々の手入力数値や更新漏れの生じる複製を持たない。
- 有効な節目0件は「節目未設定」と表示する。0/0、100%や「完了」に換算しない。
- 節目の追加・アーカイブ・復元で分母が変わる。誰が何を変えたかを履歴に残し、名称変更・並べ替えで別の節目に完了情報を移さない。
- チェック取消を可能にする。全節目が完了しても取り組みの状態は自動完了にせず、取り組みを完了にしても未完了の節目を自動で埋めない。お知らせの対応完了とも独立させる。
- アーカイブ済みの取り組み・節目は参照のみとし、更新には復元を要する。過去の担当・節目・近況は保持する。

## 権限と更新の整合性

| 操作 | 管理担当者・社長 | 方さん |
|---|---|---|
| 工程表・節目の閲覧 | 共有メンバーとして全件 | 共有メンバーとして全件 |
| 予定期間の変更 | 全件 | 不可 |
| 節目の追加・名称変更・並べ替え・アーカイブ・復元 | 全件 | 不可 |
| 節目の完了チェック・取消 | 全件 | 自分が担当する取り組み |
| 取り組みの状態変更 | 全件 | 自分が担当する取り組み |

機能内の共有メンバーである有効アカウントだけを対象とする。管理担当者と社長の同等権限、他機能の権限を変えない条件、共有メンバーの明示指定は従来計画どおり。

- 予定期間・節目構成の保存と、担当者が行う節目完了の更新を別の操作として検証する。節目チェックの要求に担当・説明・期間などの書換えを混ぜることを拒否する。
- 新しい専用処理として `setBusinessMilestoneCompletion` を追加する。対象の取り組みID、節目ID、希望する完了値、読込時の版を渡し、現在の有効アカウント・共有範囲・担当・アーカイブ状態・対象の版をサーバーで検証する。
- 版の確認と変更・履歴記録を原子的に行う。社長と管理担当者の同時変更、チェック中の担当解除、節目構成変更などを無言で上書きしない。競合時は最新情報と再確認の入口を表示する。
- 節目チェックは「反転する」要求ではなく希望値を指定する。保存中の二重操作を抑え、通信結果が不明な場合は再取得で確認する。同一状態の再送で更新日時・履歴を重複させない。
- チェック保存と近況投稿は独立する。保存失敗・競合・他者更新で編集中の報告や構成変更の入力を消去せず、未保存・保存中・失敗を区別する。
- 変更を受信しても編集中フォームを再初期化しない。ログアウト・利用者変更・共有解除後に旧データや古い応答を再表示しない。
- 節目の原文名を更新した場合は旧名の翻訳を採用しない。完了チェックや期間変更だけでは名称の翻訳をやり直さない。翻訳失敗で原文保存や節目チェックを失敗させない。
- 機能停止設定は工程表の読取、期間・節目更新、翻訳にも適用する。

## 受入条件

- 管理担当者と社長が、それぞれ直接、予定期間と節目構成を変更し、全件の節目チェック・取消を行える。方さんは担当分のチェック・取消だけを行え、管理操作・非担当分の更新はサーバーでも拒否される。
- 単月、複数月、年越し、未設定が正しく配置される。不正な月、片側だけの指定、終了＜開始が保存されない。現在位置の線は当日と一致し、範囲外では不正に表示しない。
- 節目未設定、0/3、1/3、3/3、取消、名称変更、並べ替え、追加、アーカイブ・復元で完了数と対象が一致する。期間変更や日数経過で完了数を増やさない。
- 節目全完了、取り組みの状態変更、お知らせの対応完了が互いを自動更新しない。
- 工程表と一覧の絞り込み・選択・最新情報が一致する。選択対象が絞り込みやアーカイブで外れた場合の表示を確認する。
- 同時変更、担当解除との競合、保存中の連打、応答不明時の再試行、通信失敗で入力消失・無言の上書き・履歴重複を起こさない。
- 節目名の日本語・中国語、原文表示、翻訳再試行、旧翻訳拒否を確認する。長い名称、320px程度の狭い画面、キーボード操作、色を見分けにくい場合も対象と状態を読み取れる。
- 近況投稿と、お知らせの件名・対象リンクの引継ぎが動く。打刻・日報・資料取得・お知らせ・手動更新の既存受入条件を再確認する。

## 実装の順序

1. 共通台帳で手動更新・資料取得修正01の完了、最新公開済み改善を含む確定基点、検証環境の引継ぎを確認する。
2. 第1段階の専用型・検証・権限・保存・変更履歴を実装する。予定期間と節目をこの段階から扱う。
3. 工程表、一覧、詳細、節目更新、既存お知らせへの入口を同じ取得・更新処理に接続する。
4. 日本語・中国語、翻訳失敗、入力保持、競合・通信失敗、機能停止を検証する。
5. 検証環境で3権限の受入条件と既存操作の回帰確認を行い、同じコミットの手動公開候補・復旧手順を整える。
6. 承認済み公開列に従い、公開後3営業日の利用実績を確認する。第2段階の日報メモ連携は既存重要改修02〜10の後とする。

工程表承認によって既存の公開順序、前提条件、実装ブランチ・検証環境の直列利用を変更しない。2026年9月16日に前提2件の正式完了と検証環境の引継ぎを確認し、第1段階に着手可能となった。製品コード・実装ブランチ・配備は本確認では開始していない。最新の確定基点と別作業の保護事項は[共通台帳](refactor-rollout.md)を参照する。
