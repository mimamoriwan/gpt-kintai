# 今週のTo Doから本日の業務メモへ追加

実装候補。本番未反映。基点は `tmp/weekly-todo-president` / Hosting `8b6ad165083821a4`。利用者が選択した「今日の業務メモに追加し、日報作成時に使う」方式。

## 操作

- 本人の入力欄で、今週の業務の進捗率・実績メモ・業務や目標の内容を変更すると、業務の横に「本日の日報に追加」を表示する。保存済みの進捗や実績がある既存業務も追加できる。0％で実績のない新規予定を記入しただけでは表示しない。
- 押すと未保存のTo Doを下書き保存し、保存した本人の業務名・金曜までの目標・週の進捗率・実績メモを、当日の日報の「今日の業務メモ」に追加する。To Doの共有版はこの操作では変更しない。
- 成功後は日付付きの案内と「追加済み」を表示し、追加先の日報を開ける。業務メモに「今週のTo Do」タグを使う。日報の本文・提出状態・既存メモは上書きしない。日報の作成・本人確認・正式提出は従来の操作で行う。
- 同じ日の同じ更新は、別画面・別端末・再試行でも重複しない。さらに内容を更新すれば、新しい更新として追加できる。以前追加したメモと、そこで手直しした内容も保持する。翌日は同じ業務をその日のメモとして追加できる。
- 取り下げた業務、他人の業務、過去週・未来週からは追加しない。日報を作成できる従業員・管理担当者本人を対象とし、社長の日報提出権限は拡大しない。社長の週間予定の入力・共有は維持する。

## 保存と保護

新規Callable `addWeeklyTodoToDailyReport` に `weekStart`、`itemId`、`expectedVersion`、`reportDate` だけを渡す。本文・保存先ユーザー・任意日付は指定できない。サーバーの日本時間で本日を決め、日付が変わっていた場合は再読込を案内して書き込みを拒否する。

認証中の本人・利用環境・週で決まるTo Doの保存済み下書きから原文を取得する。トランザクション内で利用者の有効状態、現在の権限、パスワードの再認証条件、利用環境、To Doの版と対象業務を再確認する。認証無効化とApp Checkも既存の保護を維持する。

既存 `workLogs` に追記する。文書IDは利用環境・本人・週・当日・固定項目ID・内容のハッシュから決定し、同じ更新を二重作成しない。既存メモがあれば書き換えない。手動で削除されたメモは再追加できる。複数の長さに分かれた場合も全件の存在を確認する。

長い業務・目標・実績は、既存の1件1,200文字の上限を守る複数メモへ分割する。文字・絵文字を途中で切り捨てない。追加可否・追加済み情報は本人の一覧応答にだけ返し、他人の下書きや業務メモを返さない。

To Do保存とメモ追加は別の処理。保存失敗時は追加せず入力を保持する。追加だけ失敗した場合は保存済みのTo Doを保持して再試行できる。競合した場合は入力を保持し、最新内容との比較を求める。追加成功後に応答だけ失われても、再試行で二重追加しない。

追加処理自体はAIや翻訳APIを呼ばない。追加したメモは従来の手動・終業後の自動日報作成の入力として扱われ、既存の自動仮作成の対象では既存の再生成処理が働く。日報本文の直接追記、To Doからの正式提出、新規の通知、Rules・Secret・実アカウントロールの変更は含めない。

## 確認と公開

`npm test`、`npm --prefix functions test`、指定の `npm test -- src/App.test.tsx src/pages/UpdatesPage.test.tsx`、`npm run build`、`npm --prefix functions run build`。架空データの確認画面では実際のTo Do画面・日報画面を使用するが、APIはメモリー内だけの代替実装で、Firebase・OpenAIには接続しない。

公開はこの修正への公開指示後に行う。現行配信を再照合し、To Doの既存4処理と新規1処理を対象指定してからHostingを反映する。他の処理・Rulesは一括公開しない。旧Hosting `8b6ad165083821a4` と公開ソース `tmp/weekly-todo-president` の既存4処理へ戻せる。追加済みのメモやTo Doは削除しない。
