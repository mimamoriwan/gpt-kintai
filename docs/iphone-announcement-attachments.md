# iPhoneでのお知らせ添付ファイル

2026-09-23、iPhone向けの画面修正を10:05:55（日本時間）に本番へ反映。実機からの失敗報告を受け、同日10:14:04にStorageのCORS設定を補正した。ユーザーのiPhone実機で「書類を開く・保存」の正常動作を確認済み。「プレビュー」「書類を保存」は白画面・無反応になるとの報告を受け、追加修正した。

## 症状と対応

既存のお知らせ添付は、取得したFirebase StorageのURLを `target="_blank"` で直接開いていた。PCでは開けるがiPhoneではFirebaseへのアクセス中に止まるという報告に対し、iPhone・iPadではファイルそのものを取得してからOSの共有メニューへ渡す経路を追加した。実際の端末ログは取得しておらず、停止原因の断定や実機での解消確認はしていない。

- ファイル名を押すとそのファイルだけを取得する。
- 取得後の「書類を開く・保存」で、対応アプリまたは「ファイルに保存」を選ぶ。ファイル名とPDF・Word・Excel・写真の形式を保持する。
- 共有メニューは取得完了後の別のタップで呼び出す。ダウンロード待機によってiOSのユーザー操作権限が切れることを避ける。
- 写真は画面内にも表示する。iPhone・iPadでの書類操作は「書類を開く・保存」に統一し、Blob URLへの移動・ダウンロードリンクは表示しない。
- URL取得とファイル取得をそれぞれ30秒で打ち切り、再試行を表示する。ファイル取得は中断し、途中・空・エラー応答を開かない。
- 閉じたときにファイル用の一時URLを破棄する。PCでは従来の直接リンクを維持する。
- Firebaseの公開権限、Storageルール、保存データは変更しない。

## 検証

- 元の作業フォルダーでは関連72件、本番ソースへ統合後は添付・お知らせ・更新情報・メニューの関連93件の画面テストが成功。
- フロントエンドの型チェックと本番ビルドが成功。
- 本番のFirebase Storage APIへ存在しない検証用パスでGETし、403応答と `Access-Control-Allow-Origin: *` を確認。実ファイル・個人情報は取得していない。実ファイルの成功応答や端末固有の通信状態は未確認。
- 公開後はiPhoneのSafariとホーム画面起動で、PDF・Word・Excelの取得、保存後の閲覧、共有のキャンセル、通信失敗後の再試行を確認する。

作業フォルダーには今回と無関係の既存変更がある。本番公開する場合は、現行本番ソースへ `InstructionAttachmentLink.tsx`・`attachmentFiles.ts` の追加、`PresidentInstructions.tsx` の添付コンポーネント差し替え、添付用スタイルのみを統合してHostingを更新する。作業フォルダー全体をそのまま公開しない。

## 実機報告を受けた配信設定の修正

実ファイルのGETは200で保存時と同じバイト数を返していたが、StorageバケットのCORS設定が空で、成功応答に `Access-Control-Allow-Origin` がなかった。このためアプリの `fetch` がブラウザの制約で失敗する。以前確認した存在しないパスの403応答には同ヘッダーがあり、エラー応答から成功応答の配信設定を推定したことが確認漏れだった。

`storage.cors.json` に、本番の `https://gpt-kintai.web.app` と `https://gpt-kintai.firebaseapp.com` からのGET/HEADだけを定義した。認証・Storageルール・ファイル本文・個別ファイルの権限は変更しない。CORS設定は `firebase deploy --only storage` では反映されないため、バケット設定として別途適用する。例えば公式CLIでは `gcloud storage buckets update gs://gpt-kintai.firebasestorage.app --cors-file=storage.cors.json` を利用する。既存設定が変わっていないか確認し、変更前の設定を保存してから反映すること。

検証では存在しないパスだけで済ませず、認可された実ファイルの200応答、保存時と一致するバイト数、正規OriginへのCORSヘッダーを確認する。iPhoneのUser-Agentを付けたHTTP要求の成功は、iPhone実機の共有操作が成功した証明ではない。

## 実機で確認できた操作への統一

CORS補正後、利用者から「書類を開く・保存」は正常動作し、Blob URLを使う「プレビュー」「書類を保存」は白画面または無反応になるとの実機報告を受けた。iPhone・iPadではネイティブのファイルメニューだけを提供する。ダウンロード失敗時のFirebase直接リンクも表示せず、その場で再試行する。共有メニュー非対応の場合はPCブラウザを案内する。共有エラーは同じボタンで再試行でき、キャンセルはエラーにしない。

Blob URLは画面内の画像表示にだけ使用し、書類では作成しない。PCの通常リンクは保持する。変更は画面と更新情報のみで、CORS・認証・権限ルールは変更しない。
