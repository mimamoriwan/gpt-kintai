# ログイン管理と専用リンクによるパスワード再設定

## 利用者の操作

指定された管理担当者のみ、サイドバーまたはスマートフォンの画面メニューから「ログイン管理」を開く。管理対象はサーバー設定で固定した3アカウント。社長の閲覧権限や別の管理担当者というだけでは利用できない。

1. 本人からパスワード忘れの連絡を受け、該当アカウントの再発行をONにする。
2. 発行された専用リンクをコピーし、本人へ伝える。この機能からメールやメッセージは自動送信しない。
3. 本人はリンクを開き、12〜128文字の新しいパスワードを設定する。
4. 完了後は自動的にOFFとなる。本人は表示されたログイン用メールアドレスと新しいパスワードでログインする。

リンクは発行から30分間有効。OFFにすると使用前のリンクを取り消せる。再発行すると旧リンクは使えなくなる。リンクは発行時にだけ表示し、画面を閉じた後に再取得できない。必要時に改めて発行する。管理担当者自身のパスワード忘れは、ログイン済みの管理画面が使えない場合、別の信頼できる復旧手順が必要。

現在のパスワードの表示・保存・他者との共有は行わない。完了後の古いログイン状態は利用できず、再ログインが必要。共通ログインも既存の本人確認規則に従う。

ログイン用メールアドレスは変更内容を確認して保存する。共通ログインの関連情報も同期する。Googleアカウント自体のメールアドレスや紐付けは変更しない。自分のログイン用メールアドレス変更後は新しいアドレスで再ログインする。

## 権限と保存

- `accountManagement/config` の `ownerUid` と `managedUids` をサーバーで確認。管理対象は重複のない3名、管理者自身を含む。
- 管理操作は現在の有効な業務プロフィール、本人に固定したUID、管理担当者ロール、最近のログインを確認する。権限確認に失敗した場合は許可しない。
- 再設定の完了はログイン不要だが、有効な専用トークンとApp Checkが必要。画面で権限を隠すだけに依存しない。
- トークン原文はデータベースに保存せず、ハッシュを用いる。URLのフラグメントに置き、画面が読み込まれたらアドレス欄・履歴から取り除く。ブラウザーの永続ストレージには保存しない。
- Auth変更とFirestore更新を一つのトランザクションにはできないため、アカウント単位の処理状態を保持する。不確定な結果は同じ入力でのみ再試行する。処理中の別の変更は拒否する。
- 処理の強制終了などで結果不明のまま残った操作は、安易な自動解除を行わず運用担当が状態を確認する。
