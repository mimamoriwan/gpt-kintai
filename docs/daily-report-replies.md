# 日報への返信通知

管理者・社長から、自分の提出済み日報にコメントがあると、アプリ内の各画面に未確認件数を表示する。通知の「返信のある日報を選ぶ」から日付を選ぶと、該当日報とコメントを開ける。過去の月の日報も対象。記録一覧のコメント欄にも確認画面への入口を追加した。

確認画面を開く・閉じるだけでは確認済みにしない。「確認しました」を押して保存成功した場合だけ、表示した返信のIDを日報の `commentsReadIds` に追加する。Firestoreの更新を購読して、各端末の未確認件数を更新する。コメントの追加と同時に確認を保存しても、操作時点で指定しなかったIDは未確認として残す。保存失敗時は確認画面と通知を保持し、再試行できる。

本人の日報だけを対象とし、本人が書いたコメント・本人確認前の仮日報を通知に含めない。管理者でも他の提出者の確認状態を変更できない。既存のCOCO/勤怠業務認証・App Check・パスワード再設定後の再ログイン・デモ範囲の保護を維持する。

既存のコメントで確認情報がないものも、初回は未確認として表示する。過去コメントを一括で確認済みにする移行は行わない。通知はアプリ利用中と次回ログイン時に表示する。メール、端末のプッシュ通知、アプリを閉じている間の通知送信は追加していない。更新情報の本文の表示は既存のメニュー選択時のみ。

## 保存と反映

追加Callable: `markDailyReportCommentsRead`。入力は `reportId` と表示済みの `commentIds`（1〜100件）。サーバーで最新アカウント状態、本人所有、デモ範囲、提出状態、既存の受信コメントIDを確認し、トランザクションの `arrayUnion` で確認済みIDを保存する。日報本文・コメント本文・提出/更新日時を変更しない。

新しいCallableとHostingだけが今回の反映対象。既存のコメント投稿CallableとFirestore/Storage Rulesの変更は不要。公開前は最新のHosting・対象関数を再照合し、公開ルールに従って承認を受けて反映する。
