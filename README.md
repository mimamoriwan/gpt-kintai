# GyoumuLog 勤怠・業務記録システム

方さんをはじめとする従業員の勤務実態と業務内容を記録し、日報から週次レポート・定例会レジュメ・月次資料へつなげる、日本語／簡体字対応のPWAです。管理担当者は記録を確認・編集し、社長は勤務状況、業務報告、フィードバックを閲覧できます。

## 現在できること

- 出社・出張・在宅・その他を選択した始業／終業記録
- 打刻忘れ・通信不良時の訂正と変更履歴
- 会社休日・振替出勤日の設定、休日勤務、非勤務理由の記録
- 3人共有カレンダーでの通常予定・出張・個人の休み・複数日予定の確認
- タグ付き業務メモからの日報作成、終業後のAI仮提出、0:15の前日分補完、本人確認後の正式提出
- 日報・商品記録の中国語原文保存、日本語版生成、失敗時の再実行
- 業務メモごとの写真・PDF・Word・Excel・Webリンク添付と容量制限
- 日報AIによる添付資料の内容確認、同一入力キャッシュ、管理画面での月別・利用者別の利用回数確認
- 商品候補・発見理由・確認状況・変更履歴の記録
- 週次計画、AI週次レポート、定例会レジュメ、フィードバックの記録
- Google Drive上の成果物・関連資料の索引と、月次JSON／CSV／印刷用HTML出力
- 雇用・職務基準と在留更新準備の補助記録
- 管理担当者による確認、修正後の再確認表示、会社カレンダー・利用者・カテゴリ管理
- 全社員から個人・自分以外の全員へ発信できる、優先度・期限・添付資料付きお知らせ、確認・対応状況、日本語／中国語の双方向自動翻訳
- 社長はお知らせと共有予定を登録でき、その他の記録は閲覧専用
- Firebase Security Rules、Custom Claims、App Checkによる権限制御

## 当面の開発範囲

本システムでは、勤務実態の記録、日報、週次報告、定例会でのフィードバック、月次資料、将来のCOCOシステム連携に必要な社内運用を優先します。

リアルタイム音声翻訳、商談録音、自動議事録作成は現在の対象に含めません。これらは `translate_app` で独立して開発し、将来必要になった場合に、勤怠とは別の商談カテゴリーまたは別サービスとして連携方法を検討します。

## ローカル確認

```bash
npm install
npm --prefix functions install
npm run build:all
npm run emulators
```

別のターミナルで次を実行します。

```bash
npm run seed
npm run dev
```

デモ用アカウントは `scripts/seed-emulator.mjs` に記載されています。デモの認証情報を本番では使用しないでください。

## テスト

```bash
npm test
npm --prefix functions test
npm run test:rules
```

本番準備は [Firebase本番設定](docs/firebase-setup.md)、日常運用は [運用手順](docs/operations.md) を参照してください。
